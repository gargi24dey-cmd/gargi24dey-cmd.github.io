Predicting Restaurant Rating Categories

Random Forest vs Logistic Regression: A Comparative Analysis of Zomato and Swiggy

This project uses machine learning classification techniques to predict restaurant rating categories and compares model performance across two food-delivery platforms — Zomato and Swiggy — focusing on restaurants in Bangalore. The workflows were built in Orange Data Mining to keep the analysis reproducible, comparing Random Forest and Logistic Regression to see which performs better at predicting rating categories.

Project Objectives

  • Predict whether a restaurant belongs to a Low, Medium, or High rating category
  • Compare the performance of Random Forest and Logistic Regression
  • Identify how cost, votes, services, and restaurant type differ across rating categories
  • Compare rating patterns and model performance between Zomato and Swiggy

Dataset

Zomato Bangalore Restaurants

Source: Kaggle — Zomato Bangalore Restaurants Dataset. Raw records: 51,717; records after cleaning: 41,418 (~80% retention). Rating categories: Low (<3.5), Medium (3.5–4.0), High (>4.0). Features used: online_order, book_table, votes, rest_type, listed_in(type), cost_clean, and platform.

Swiggy Bangalore Restaurants

Source: Kaggle — Swiggy Bangalore Restaurants Dataset. Raw records: 10,298; records after cleaning: 1,499 (~14.6% retention), using area, category, and cost_clean. The Swiggy dataset had many missing ratings, and no restaurant in the cleaned sample scored above 4.0 — making this predominantly a Low/Medium classification problem.

Data Cleaning

Preprocessing included parsing rating values (e.g. "4.1/5"), converting cost into numeric values, handling unusable entries like "NEW" or "–", removing observations without a usable rating, creating the target variable rating_class, and encoding categorical variables — all performed within Orange's Python Script widget to keep the workflow reproducible.

Machine Learning Models

Logistic Regression — used as a linear, interpretable baseline, assuming additive relationships between predictors and outcome.

Random Forest — an ensemble of decision trees, chosen since restaurant characteristics (e.g. cost and popularity) likely interact non-linearly.

Workflow

Dataset → Python Script → Select Columns → Preprocess → split into Logistic Regression and Random Forest → Test & Score → Confusion Matrix. A similar workflow was built for Swiggy. Evaluation used 5-fold stratified cross-validation.

Key Findings

Zomato

ModelAUC
Random Forest0.928
Logistic Regression0.778

Random Forest outperformed Logistic Regression by a 19.4 percentage-point accuracy margin, suggesting rating patterns involve non-linear relationships better captured by tree-based models.

Swiggy

ModelAUC
Random Forest0.537
Logistic Regression0.600

Both models performed only slightly better than random classification — largely because only 1,499 restaurants had usable ratings, and ~82% fell into the Medium category, leaving little variation for the models to learn from.

Business Insights

Cost and rating: a one-way ANOVA showed a strong association between cost and rating category (F = 4708.6, p < 0.001) — higher-rated restaurants generally had higher costs, though this reflects association rather than causation.

Votes and rating: customer engagement, proxied by votes, also differed significantly across categories (F = 5866.1, p < 0.001), with higher-rated restaurants showing substantially greater engagement.

Platform differences: model performance depended as much on data structure and quality as on the algorithm — Zomato had much more variation across rating categories, while Swiggy was heavily concentrated around Medium.
